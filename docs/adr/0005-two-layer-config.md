# Two-layer config: client-neutral run config, per-client config

`core/config.toml` holds only client-neutral values: a global section, `[roles.<role>]` and `[roles.<role>.tasks.<task>]`, resolved task > role > global (model tier `1`–`4`, effort, templates, dirs, exact commands, output destination). Each client has `core/clients/<name>.toml`: a global section of its own defaults (Claude Code: flags, tier → model, effort, env) and the same `[roles.<role>]` / `[roles.<role>.tasks.<task>]` layout for additions (Claude Code: extra `--allowedTools` rules; skill: the description, and `output` type `orchestrator` for tasks whose deliverable goes back to the orchestrator), resolved task > role > client global. A client entry with the same name as a neutral one (`output`) replaces it for that client. Retargeting a client or swapping a model edits one client file, never a task.
