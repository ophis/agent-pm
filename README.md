# agent-pm

Runs agent roles and tasks from the Linear board (team Frank's Agents): each runnable project has one role (who: charter, memory, read-only scope) doing one task (what: the procedure). Runnable today: Deep Research (picks the next Todo issue, runs `/deep-research` once, pushes the report to `~/playground/private_docs/Research/` (GitHub `ophis/private_docs`), links it from the issue), Product Design (a PRD in `private_docs/Product Design/`) and Engineering (builds the PRD with `autopilot:build` in the issue's target repo and opens a PR). Promote hands reviewed issues to the next project.

This repo holds the code and the run state:

- `logs/` (gitignored) — never clean it out: `runs.log` is also runner state.
  - `runs.log` — `start` / `resume` / `end` lines per run (issue, session ID); the source for resuming and for the attempt cap. Pruned to 7 days each tick. Lost → nothing is resumed.
  - `router.log` — each tick's decisions. `projects/<task>.log` (named after the task) — each run's launch line, claude output and end line. `promote.log` — promote's output (one line per action, or one `nothing to do` line per run).
- `work/<ID>/` (gitignored) — the cwd of every run for issue `<ID>`, created by the launcher; an Engineering run's worktree is `work/<ID>/worktrees/<branch>`, its PR body `work/<ID>/pr.md`. Claude keeps the run's transcript in `~/.claude/projects/<cwd with non-alphanumerics as ->/<session-id>.jsonl`, where the router looks for it. Nothing removes these directories yet.

Code:

- `roles/` — `principles.md`, the rules shared by every role and task; per role a pair: `<role>.md`, the charter, and `<role>.toml`, its settings (may be empty): `read_only` (absolute paths or `{repo}`) and `memory` (an existing dir that overlaps neither the repo, the role's `read_only`, `~/.claude` nor `~/Library/LaunchAgents`, in either direction).
- `tasks/` — per task a pair: `<task>.md`, the procedure Claude follows (each must define a resume rule), and `<task>.toml`: `model`, `effort`, `add_dirs`, `repo_from_issue` (the launcher's repo step) and `allowed_tools` (empty by default; exact `--allowedTools` rule templates over `{worktree}` `{branch}` `{owner}` `{name}` `{default}` `{clone}`, no `*`, only with `repo_from_issue`; add one only if a supervised run shows the classifier stopping a push). A file without its pair, an unknown key or a bad name stops the router and launcher. The launcher passes the principles, charter and task paths in the prompt, plus the role's memory dir when set.
- `templates/` — document skeletons a task fills in (`prd.md` for Product Design).
- `scripts/router.py` — one tick: hours check (02:00–06:59; `--now` skips it), tmux lock (`agent-pm`), a registry guard (the tick stops, dry-run too, while `roles/` or `tasks/` has a tracked change or an untracked or ignored `.md`/`.toml` file; Edit deny rules don't stop a run's Bash writes there), prune, Recover across runnable projects, plan, usage probe only when there is work, then resume an interrupted In Progress issue or claim a new one (priority, then later stage, then oldest) and call `launch.py`. Both need the probe not rejected, 5-hour usage < 90% and weekly windows not full (`MAX_5H`). `--dry-run` changes nothing and starts no run; `--now --issue ID` starts a specific Todo issue; `--pick [--project ID]` = Recover + Pick + Claim (task step 1). Unknown flags exit 2.
  - Scheduled hourly 02:00–06:00 by `~/Library/LaunchAgents/com.ophis.agent-pm.router.plist`; source: `scripts/com.ophis.agent-pm.router.plist`.
  - Watch: `tmux attach -t agent-pm`. Inspect a run: `cd work/<ID> && claude --resume <session-id>`.
- `scripts/launch.py` — starts one run from the project's role and task (their `roles/` and `tasks/` pairs) in tmux, cwd `work/<ID>/`; called by the router. Every run gets `--setting-sources user --strict-mcp-config` (no project-scoped CLAUDE.md, settings, hooks, skills or MCP servers load; user plugins do), `--add-dir` for `roles/`, `tasks/`, `templates/`, the task's `add_dirs` and the role's `memory` (not the repo root), Edit deny rules for `roles/`, `tasks/`, `templates/`, the worktrees' `.git` files and the role's `read_only`, and a `Reviewer: <email>. Humans: <emails>. Project: <id>.` prompt line. A resume whose transcript is missing exits 3 without a run.
  - Repo step, for `repo_from_issue` tasks: reads the issue's `Repo:` line, checks push access, clones `~/playground/<name>` when missing and picks the `<ID>-<slug>` branch. OK → a `Repo check: OK …` prompt line and env `AGENT_PM_ISSUE`; invalid (user-fixable) → `Repo check failed: <reason>` and the run bounces the issue (on resume: treated as transient); both add an `eng.py: python3 <ROOT>/scripts/eng.py.` line, the command the task runs; transient → a `transient` line in the project log, exit 3, no run (Recover later returns the issue to Todo). A role `memory` overlapping the issue's clone or `work/<ID>/worktrees` is a config error: a `config-error` line in the project log, exit 2, no run.
- `scripts/eng.py` — Engineering: the repo step's `resolve`, and for the task `eng.py status` (repo, branch, worktree, PR, autopilot plan docs, a shell-safe `pr_title`) and `eng.py comments --since ISO` (PR comments and reviews by the user's `gh` login only), for the issue in `AGENT_PM_ISSUE`. The agent does the git and `gh` writes itself; `eng.py` is a correctness aid, not a security boundary.
- Engineering: approve a PRD by moving it to Handoff with a comment `Repo: <owner>/<name>` (`https://github.com/<owner>/<name>`, `git@github.com:<owner>/<name>.git` and a Linear link to either also work). The run builds the PRD's first phase (or the phase the comments name) with `autopilot:build`, commits its spec and plan doc in the target repo (where it keeps design docs, else `autopilot_docs/`) and links them in a `Build docs:` comment, pushes `<ID>-<slug>`, opens the PR and comments `Build ready:`; Linear's GitHub integration moves the issue to In Review. Comments on the issue or the PR, then moving it back to Todo, continue on the same branch and PR.
- `scripts/pipeline.py` — shared: Linear API, paths, config. Needs the agent account's API key in the macOS Keychain:
  - Store: `security add-generic-password -a frank.agent.w -s linear-api-key -w` (prompts for the key).
  - Read: `security find-generic-password -a frank.agent.w -s linear-api-key -w` per call; the key is sent only as the `Authorization` header to `api.linear.app`, never printed or written to disk. Works under launchd because the LaunchAgents run in the login session.
- `scripts/promote.py` — Handoff: for each issue in the `Handoff` status whose project has a `next` in `pipeline.toml`, after it has been in `Handoff` for 10 minutes (an undo window; `--now` skips it for a manual run), creates the next project's issue (Todo, related, with the source links, the `human_members` users' comments since the last review as instructions, and every source comment quoted for context) and moves the source to Done; no comment → back to In Review with a question, unless the source project sets `require_instructions = false`. Enabled: Deep Research → Product Design (PRD), Product Design → Engineering (TDD, comments optional). No LLM. `--dry-run` changes nothing. Runs at :05, :20, :35 and :50 via `com.ophis.agent-pm.promote` (source `scripts/com.ophis.agent-pm.promote.plist`, `/opt/homebrew/bin/python3`). Design: `docs/specs/2026-09-27-promote-design.md`.
- `pipeline.toml` — team, `human_members` (the first is assigned every issue moved to In Review: by the tasks, router and promote) and projects keyed by Linear project id (names and URL slugs change on rename; a comment names each): `next` (the project a Handoff creates an issue in), `prefix` (title prefix of issues created there), `require_instructions` (default true), and `role` + `task` for runnable ones; nothing else (other keys stop the router and launcher).
- `scripts/tests/` — `python3 -m unittest discover -s scripts/tests` (Python 3.11+; no network, Keychain or Claude).
- Resuming (Deep Research): the router resumes the same session (`claude -p --resume <sid>`) with a prompt to re-read `roles/principles.md`, the charter and `tasks/deep-research.md` and follow the task's resume rule. The resumed session reuses the interrupted deep-research run's saved result (or its journal if the run was killed) and re-runs only missing agents (e.g. 3 fresh votes for a claim with fewer than 2 valid votes); it never uses `resumeFromRunId` (that replays only the unchanged prefix of agent calls, so deep-research re-runs almost everything) and never moves the issue to Todo.
- Design: `docs/specs/2026-09-27-auto-resume-design.md`, amended by `docs/specs/2026-09-27-resume-candidate-fix-design.md`, `docs/specs/2026-09-27-resume-from-saved-result-design.md`, `docs/specs/2026-09-27-router-launcher-design.md`, `docs/specs/2026-09-28-task-44-role-task-design.md` and `docs/specs/2026-09-29-task-44-role-task-pairs-design.md`.

Notes:
- `launch.py` sets `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`; `claude -p` otherwise kills the research workflow after 10 idle minutes.
- One research run costs roughly 40% of the 5-hour window at `--effort xhigh`.
- Deploy a change to the run directory only when no Deep Research or Product Design issue is In Progress: a session started in `work/` cannot resume in `work/<ID>/`.

## Rescheduling

Edit `StartCalendarInterval` in `scripts/com.ophis.agent-pm.router.plist`, copy it to `~/Library/LaunchAgents/`, then reload (launchd reads the plist only at load). Keep the hours window in `router.py` in sync. The same steps install or reload `com.ophis.agent-pm.promote`. launchd does not create `logs/` and cannot start a job whose log directory is missing, so create it first.

```bash
mkdir -p ~/playground/agent-pm/logs
P=~/Library/LaunchAgents/com.ophis.agent-pm.router.plist
plutil -lint $P
launchctl bootout gui/$(id -u)/com.ophis.agent-pm.router
launchctl bootstrap gui/$(id -u) $P
launchctl print gui/$(id -u)/com.ophis.agent-pm.router | grep -A3 descriptor   # confirm the new time
```

Stop the schedule: `launchctl bootout gui/$(id -u)/com.ophis.agent-pm.router` (plus delete the plist, or it loads again at next login).
